# Оценочный набор (BormoChecker Evaluation Suite)

Эталонный набор состоит из **24 текстов** и **146 размеченных утверждений**, а также трёх контрольных кейсов (`Dabro`, `Лось и заяц`, `МИЭТ`) в `eval/reference_cases/`.

## Канонический раннер оценки

Точка входа для прогона бенчмарка — `bormochecker/scripts/eval_factcheck_benchmark.py`.

```bash
# Офлайн-прогон по сохранённым фикстурам (воспроизводимый, без сети, 3 повтора)
.venv/bin/python -m bormochecker.scripts.eval_factcheck_benchmark --offline --runs 3

# Прогон по отладочной выборке (dev, 16 текстов)
.venv/bin/python -m bormochecker.scripts.eval_factcheck_benchmark --split dev --offline

# Прогон по контрольной выборке (holdout / test, 8 текстов)
.venv/bin/python -m bormochecker.scripts.eval_factcheck_benchmark --split holdout --offline

# Прогон одного кейса с фиксированным моментом времени
.venv/bin/python -m bormochecker.scripts.eval_factcheck_benchmark --only m06 --reference-datetime 2026-09-26T12:00:00Z
```

### Артефакты прогона (`runs/<YYYYMMDD-HHMMSS>_<commit>/`)

Каждый запуск создаёт изолированный каталог в `runs/` со следующими файлами:
- `manifest.json` — git commit, грязность дерева (`dirty`), split, число повторов (`runs`), `offline`, `reference_datetime`, провайдер и модель LLM (`temperature`, `seed`), SHA-256 хеши всех файлов эталона.
- `raw/<item_id>.json` (или `raw/run_N/<item_id>.json`) — полные сырые JSON-ответы `Report` по каждому тексту и контрольному кейсу.
- `scores.json` — рассчитанные метрики, confusion matrix, показатели нестабильности (`instability`) между повторами и проверка порогов `eval/dod.yaml`.
- `report.md` — сводный человекочитаемый отчёт, сгенерированный исключительно из `manifest.json` и `scores.json`.
- `run.log` — полный лог прогона.

## Структура каталога `eval/` и `items/<id>/`

- `eval/dod.yaml` — формальные пороги Definition of Done (DoD).
- `eval/splits.json` — фиксированное стратифицированное разбиение 24 текстов по событиям:
  - `dev` (16 текстов): для отладки промптов, лемматизации и поиска;
  - `holdout` (8 текстов): контрольная выборка, на которой запрещено подбирать эвристики.
- `items/<id>/` (хранится вне git, путь задаётся через `--eval-dir` или переменную окружения `FACTCHECK_EVAL_DIR`):
  - `text.txt` — проверяемый исходный текст;
  - `gold.json` — эталонная разметка утверждений (`claims`), метаданные источника (`source_url`, `published_at`) и описание внесённых искажений (`modification` для префикса `m`);
  - `documents/` — сохранённые первоисточники для офлайн-проверки.

| Префикс | Количество | Описание |
|---|---|---|
| `r` | 12 | Реальные новости от 20–22.09.2026 с сохранёнными первоисточниками в `documents/`. |
| `m` | 9 | Модифицированные копии `r` с намеренно внесёнными фактическими ошибками (числа, даты, арифметика, модальность). Искажённая копия всегда находится в том же сплите (`dev` или `holdout`), что и оригинал. |
| `s` | 3 | Синтетические тексты: демо-текст защиты, мнения/прогнозы, вымышленное событие. |

Распределение эталонных вердиктов (146 утверждений): `55 supported`, `55 unresolved`, `12 partially_supported`, `12 contradicted`, `12 not_checkable`.

## Правила разметки и расчёта метрик

1. **Сопоставление по спанам (`score_item`):**
   Эталонному утверждению сопоставляются все извлечённые утверждения, которые лежат внутри эталонной цитаты (не менее 50% своей длины) или покрывают её (не менее 50% длины эталона). Все перекрывающиеся предсказания помечаются как сопоставленные (`matched`), чтобы атомарное разбиение длинного предложения не порождало ложных срабатываний на неразмеченном тексте.
2. **Агрегация вердикта:**
   По сопоставленным частям берётся наиболее строгий вердикт: `contradicted` (`error`) → `unresolved` (`clarify`) → `partially_supported` → `supported` (`confirmed`).
3. **Учёт сбоев:**
   Таймаут, исключение или пустой ответ модели не выбрасываются из знаменателя: кейс засчитывается как отказ (`failed_cases`), а его эталонные ошибки считаются пропущенными.
4. **Согласованность разметчиков (IAA):**
   При двойной разметке (`annotator_1`, `annotator_2` в `gold.json`) рассчитывается коэффициент согласия Коэна ($\kappa$). Спорные случаи документируются в поле `note`.

## Хранение эталонного набора

В `items/*/text.txt` и `documents/` содержатся тексты публикаций для воспроизводимых прогонов (`eval/MANIFEST.sha256`). Каталог `eval/items/` подключается локально через `--eval-dir` или переменную окружения `FACTCHECK_EVAL_DIR`; при отсутствии локального корпуса тесты, требующие `items/`, корректно пропускаются через `pytest.skip`.
