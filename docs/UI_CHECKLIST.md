# Чеклист проверки веб-интерфейса BormoChecker (`bormochecker/static/index.html`)

Документ фиксирует сценарии регрессионного тестирования интерфейса фактчек-пульта (автоматизированные проверки в `tests/test_ui_static.py` и ручная проверка в браузере).

**Дата последней проверки:** 2026-11-12
**Статус:** Все сценарии проверены и подтверждены (`test_ui_static.py`).

---

## Подготовка окружения

1. Запуск сервера фактчека:
   ```bash
   .venv/bin/python -m uvicorn bormochecker.web:app --host 127.0.0.1 --port 8612
   ```
2. Открыть в браузере:
   ```text
   http://127.0.0.1:8612/
   ```

---

## Сценарии проверки

### 1. Загрузка страницы и доступность
- [x] Страница открывается без ошибок в консоли разработчика (`F12` -> Console).
- [x] В сайдбаре отображается статус фактчек-пульта (`Гостевой режим (0 ₽)` или `Редакция (полный доступ)`).
- [x] Присутствует поле ввода текста с ограничением 10 000 знаков и подсказкой:
  «Лимит: 10 000 знаков на проверку. Для больших статей проверяйте текст по смысловым блокам».
- [x] Счётчик знаков отображает `0 / 10 000` и корректно обновляется при вводе текста.
- [x] Селектор режимов (`#checkMode`) связан с `<label for="checkMode">`:
  - В гостевом режиме (`q.role === 'guest'`) недоступные гостю режимы (`journalism_full`) скрыты согласно `q.guest_modes`, отображается подсказка `#modeHint`.
- [x] Клавиатурная навигация и контрастность: фокус перемещается по `Tab`, видимый контур `:focus-visible` присутствует, контраст текста и бейджей не ниже `4.5:1` (WCAG AA).

### 2. Проверка текста с API / заглушкой
- [x] Нажать кнопку «Загрузить пример»:
  - Заполняется поле текста нейтральным образовательным примером (не пересекающимся с эталонным бенчмарком).
  - Заполняется контекст и выбирается режим.
  - Появляется всплывающее уведомление (тост) с названием примера.
- [x] Нажать «Проверить материал» (или `Ctrl+Enter`):
  - Кнопка блокируется (`disabled`), показывается индикатор загрузки.
  - Отправляется запрос `POST /api/check`.
- [x] После получения ответа:
  - Открывается секция `#report` (`aria-live="polite"`).
  - Отображается итоговый балл, статус проверки и момент проверки (`rep.reference_datetime`).
  - В тексте `#reportMarked` подсвечены проверенные фрагменты с корректной обработкой `start === null || end === null`.
  - Ссылки на источники в карточках содержат вид источника (`source.kind`) и место в документе (`source.location`, например `[page: N]`).
  - Таблица расходов содержит детализацию токенов, вызовов модели и поиска.

### 3. Пустой результат и граничные случаи
- [x] Нажатие «Проверить материал» при пустом поле текста не отправляет запрос, переводит фокус в поле и показывает тост «Добавьте текст материала».
- [x] Проверка текста без проверяемых фактов:
  - Итоговый балл отображается как `—` (тире, а не `100%`).
  - Заголовок отчёта: «Проверяемых утверждений не найдено».
- [x] Проверка со статусом `partial`:
  - Заголовок отчёта содержит предупреждение `⚠️ Частичная проверка...`.
  - В блоке ограничений выводится список утверждений, оставшихся непроверенными.

### 4. Ошибка сервера
- [x] При сбое (HTTP 500 / 422 / 503):
  - Показывается тост: «Проверка не выполнена: <текст ошибки>».
  - Индикатор загрузки скрывается, кнопка «Проверить материал» разблокируется.
  - Введённый пользователем текст сохраняется без потерь.

### 5. Отказ буфера обмена
- [x] Вызов `navigator.clipboard.writeText` обёрнут в `try/catch`.
- [x] При отказе Clipboard API срабатывает запасной способ через временное поле `<textarea>` и `document.execCommand('copy')`.
- [x] При блокировке обоих механизмов выводится понятное сообщение об ошибке: «Не удалось скопировать в буфер обмена: выделите и скопируйте текст вручную».

### 6. Безопасные правки (`applySafeSuggestions`)
- [x] Кнопка «Применить безопасные правки» автоматически заменяет только фрагменты с меткой `error`, у которых есть проверенный источник и точная замена (по символьным координатам `start`/`end` с обратной сортировкой).
- [x] Предложения с меткой `clarify` не применяются автоматически: они выводятся отдельным списком `#clarifyManualSection` с кнопками «Применить вручную» для каждого пункта.

### 7. Опрос очереди (`/api/queue`)
- [x] Опрос `/api/queue` выполняется только при наличии активной задачи или ожидания в очереди и останавливается в состоянии покоя.
- [x] При скрытии вкладки (`document.hidden`, событие `visibilitychange`) таймер опроса приостанавливается и возобновляется при возврате на вкладку.
- [x] При ошибках сети интервал опроса экспоненциально увеличивается: `4 с → 8 с → 16 с → 30 с`.
