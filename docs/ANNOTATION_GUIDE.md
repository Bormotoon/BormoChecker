# Руководство по разметке эталона фактчекера (Annotation Guide)

> Документ регламентирует процедуру независимой ручной разметки фактологических кейсов.
> Вторая разметка и расширение выборки `holdout` выполняются человеком-экспертом.

---

## 1. Цели разметки

Цель разметки — создание несмещенного, воспроизводимого «золотого стандарта» (Gold Standard) для контроля качества фактчекера новостей образования.

Каждый кейс состоит из:
1. Исходного текста новости (`text.txt`).
2. Описания инфоповода и события (`event`).
3. Набора атомарных утверждений (`claims`) с точной цитатой и эталонным вердиктом.
4. Приложенных официальных документов (`docs/` и `docs.json`).

---

## 2. Принципы выделения утверждений (Claims)

1. **Атомарность**: каждое утверждение проверяет ровно один факт. Сложные предложения с несколькими фактами (дата + число участников + место) разбиваются на отдельные записи.
2. **Точная цитата (`quote`)**: цитата должна являться точной подстрокой из `text.txt` (без изменения регистра и пунктуации).
3. **Фактическое ядро**: субъективные мнения, художественные эпитеты и реклама отделяются от проверяемых фактов.

---

## 3. Эталонные вердикты и соответствие меткам системы

| Вердикт разметчика (`verdict`) | Значение | Соответствующая метка системы (`Label`) |
|---|---|---|
| `supported` | Факт полностью подтвержден официальными источниками или арифметикой | `Label.confirmed` (зеленый) |
| `contradicted` | Факт явно опровергнут источниками, содержит ошибку в дате, числе, нормативе или логике | `Label.error` (красный) или `Label.clarify` (желтый) |
| `partially_supported` | Факт верен лишь частично (например, относится к бакалавриату, но не к колледжу) | `Label.clarify` (желтый) |
| `not_checkable` | Факт в принципе невозможно проверить по открытым источникам (прогноз, внутренняя оценка) | `Label.clarify` (желтый) или `Label.opinion` (синий) |
| `unresolved` | Источников недостаточно для вынесения однозначного решения | `Label.clarify` (желтый) |

## 4. Шаблон разметки для второго разметчика

Шаблон файла разметки кейса (`gold.json` или `second_annotator_<case_id>.json`):

```json
{
  "annotator_id": "annotator_2",
  "case_id": "m01-tuchka-cena",
  "date": "2026-11-15",
  "event": "Цены на билеты спектакля «Тучка»",
  "claims": [
    {
      "quote": "Билеты стоят от 500 рублей",
      "verdict": "supported",
      "source_url": "https://theatre.ru/tickets",
      "notes": "Подтверждается официальной афишей театра"
    },
    {
      "quote": "Премьера состоится 30 февраля",
      "verdict": "contradicted",
      "source_url": "",
      "notes": "Несуществующая календарная дата"
    }
  ]
}
```

## 5. Оценка согласованности разметчиков (Cohen's Kappa)

При получении разметки от второго эксперта вычисляется коэффициент каппа Коэна ($\kappa$):

```python
from bormochecker.agreement import cohen_kappa

# Списки вердиктов по совпадающим утверждениям:
labels_annotator_1 = ["supported", "contradicted", "partially_supported", "supported"]
labels_annotator_2 = ["supported", "contradicted", "clarify", "supported"]

kappa = cohen_kappa(labels_annotator_1, labels_annotator_2)
print(f"Cohen's Kappa: {kappa:.3f}")
```

### Шкала интерпретации согласия (Landis & Koch):
- **$\kappa \ge 0.81$**: Почти идеальное согласие (Almost Perfect) — эталон готов к валидации.
- **$0.61 \le \kappa \le 0.80$**: Существенное согласие (Substantial) — мелкие расхождения разрешаются консенсусом.
- **$0.41 \le \kappa \le 0.60$**: Умеренное согласие (Moderate) — требуется доработка гайдлайна и повторный раунд.
- **$\kappa < 0.41$**: Неприемлемо низкое согласие.
